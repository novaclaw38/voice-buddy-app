## Design Specificity Verdict

LLM assessment: borderline-generic chassis around a genuinely specific voice-interaction core (ask-first parent messages, karaoke highlighting, calm wind-down screens). Parent Dashboard is a stock tabbed-settings layout. The new alternating backdrop feature is the least specific addition — five interchangeable stock-fantasy scenes chosen at random with no relationship to what Buddy is doing.

Deterministic scan: 52 CLI findings, all bounce-easing, across 22 files (none in the new WorldBackdrop.module.css, correctly). Browser overlay across 5 live pages found 36 more findings; landing page alone had 21, including 5 low-contrast failures (2.1:1 and 1.9:1, both under the 4.5:1 floor) and 2 undersized-ui-text (10px). Child page had 6, including text-occlusion. Coverage gap: detector's contrast rule only samples solid CSS colors, not rendered image content, so it can't see backdrop-related legibility risk.

Corroboration: both assessments independently found the Courses page broken via different methods (code read vs. live DOM), converging on the same P0.

## Overall Impression

Real, specific craft in a handful of voice-interaction moments, undercut by a fully broken Courses page, a brand-new backdrop feature that contradicts the app's own day/night mood system, and a Parent Dashboard that's outgrown flat tabs.

## What's Working

1. Ask-first pattern for parent messages/stories — reused consistently across three screen states.
2. Camera consent confirmation copy — unusually honest for a feature that could feel invasive.
3. Karaoke word-highlighting synced by character-weight — bespoke craft for pre-readers.

## Priority Issues

[P0] Courses page renders a raw parser error to users. Confirmed independently by both assessments, reproducible every load. Fix: catch the fetch/parse failure, map to a Buddy-voiced retry message, never surface err.message to end users. Suggested command: /impeccable harden

[P0] The new backdrop feature is time-of-day-blind, contradicting the app's own mood system. Confirmed via DOM inspection at night: rainbow-meadow.webp (daytime scene) shown under partOfDay: night. Fix: gate scene pool to match partOfDay, or generate day/night variants. Suggested command: /impeccable polish

[P1] Backdrop and existing CSS decorations visually clash — two unrelated art styles stacked (photo + flat-vector sun/moon/emoji), ground-plane SVG now invisible, avatar reads as a sticker on a photo. Fix: match decoration style to the new backdrops, or suppress CSS decorations when a photo backdrop is active. Suggested command: /impeccable polish

[P1] Parent Dashboard's 9-tab bar exceeds cognitive-load budget (4/8 checklist items failed). TAB_GROUPS labels exist in code but are never rendered; no scroll affordance. Fix: render group.label as caption headers, add scroll-edge fade/chevron on mobile. Suggested command: /impeccable layout

[P1] Landing page has concrete WCAG contrast failures — white-on-#ff9a3c at 2.1:1, footer text at 1.9:1, both under the 4.5:1 AA floor; two 10px text instances below the 11px floor. Suggested command: /impeccable audit

## Persona Red Flags

Jordan (confused first-timer): AvatarPicker has no voice narration unlike the rest of the app; Today's Activity card overlaps Buddy's name tag at mobile width; icon-only dock below 499px loses labels a young child needs.

Sam (accessibility-dependent): window.confirm() breaks the app's focus-trap dialog system; Courses uses <h2> for both group and item labels, flattening heading hierarchy; 9-tab tablist overflows with no group-label announcement.

Riley (stress tester): Courses failure is the default state, not an edge case; a bad/missing lesson id for a Pro user would render a blank white screen with no recovery path (not directly observed, worth hardening).
